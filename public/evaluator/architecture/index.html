Evaluator architecture

The evaluator is a synthetic consequential world.

A visitor can connect intelligence to a fake world, run declared operations, inspect the state transitions, and export evidence. No real money, credentials, cloud systems, hardware or production KORE deployment is required.

Boundary.
The evaluator tests CR semantics over synthetic state. Production KORE is the later question of enforcing those semantics against reality.
Three things people confuse

Evaluation harness, agent harness, consequence runtime.

01 · Evaluation harness

Runs tasks and grades world state

Supplies synthetic tools, state, scenarios, graders, traces and exports.

 02 · Agent harness

Makes a model act

Prompts, tools, memory, retries, scaffolding and the model-facing loop are brought by the participant.

 03 · Consequence runtime

Enforces against reality

Production VALIS/KORE mediates real authority, real execution and real-world effects. That is a separate stage.

The evaluator grades the state of the synthetic world, not the agent's claim about the world. If an agent says it completed $120 of synthetic spend but the state says $60, the agent did not succeed.

BYO agent

Local first. Provider agnostic.

Bring Your Own Agent means the participant supplies the intelligence implementation and connects it to the local synthetic tool surface. The evaluator should not require RecursiveSettlement.com to hold model API keys, execute arbitrary uploaded code, or host public agent runs.

The agent can be Claude, GPT, Gemini, a local model, a deterministic planner, a human, or a custom research system. CR evaluates consequential transitions on the consequence side.

Production boundary

Do not require integration before evaluation.

EvaluatorTheir problem -> synthetic CR representation -> evaluation -> evidence.
Production KOREOnly after correspondence exists: real agent -> real settlement -> real execution -> real world.

Munich does not need production KORE to examine risk correspondence. A frontier lab does not need production VALIS to study capability-consequence separation. An engineer does not need to trust the implementation to independently reproduce the semantics from a frozen corpus.
